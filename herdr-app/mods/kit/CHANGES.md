# 改動紀錄

## 1.12（2026-11-21）
- 倉庫和 agent 的 Kit 視窗每一列寫版本（淡色小字）：自己寫的「11/21 版」，同一天改好幾次「11/21 版（3）」，改了還沒送出寫「改了還沒送出」；收來的「原作者 11/10 版」。滑鼠停上去看完整日期、commit 訊息、指紋（要 kit api 1.14）
- agent 的 Kit 視窗：這個 agent 讀的不是最新的，那一列標「舊版」，下面寫原因和怎麼辦：「這台還沒同步（最新是 11/21 版）」或「這次對話開始後改過（11/21 版），開新對話才會讀到」
- agent 的 Kit 視窗最上面一行：「全部最新」或「3 項舊版：開新對話才會讀到」；kit 太舊時寫「那台的 kit 太舊，更新後才看得到版本」
- 「舊版」看的是 agent 自己的程式（不是包著它的 shell）開始的時間，並告訴 kit 它是哪種 agent，判斷才準；各機器分頁：kit 0.9.0 以前的寫「缺：版本和舊版」
- 排隊的重新載入和規則訊息：那個 agent 的標題列不在畫面上也會送（任何一個標題列每 1.5 秒看一次全部），不會等到 30 分鐘取消
- 排了好幾則就一則一則送、照順序：前一則送出 2 秒後、它又停下來才送下一則（omp 重新載入要重連 MCP，不會在那時打進下一則）
- 用別的帳號（例如 root）跑的 agent 不再收到 /reload-plugins 和規則訊息（它的 kit 不是這個）
## 1.11（2026-11-21）
- Codex 不用重開了：規則它每一輪都會重讀，不用做什麼；MCP、外掛打 /new 開新對話就會讀到
- 加上或拿掉規則，不用關掉 agent：開著的 Claude、omp 會收到一則訊息「kit 剛把規則 X 加到整個帳號：請先讀 <路徑>，之後照它做」（拿掉：之後不用再照它做）；它在忙就排隊，停下來才送，跟重新載入一起排、照順序送
- agent 視窗排版：外掛那列右邊只寫「只能加到整個帳號」，介紹不再被擠成一欄；外掛裡面有什麼放一行，太長截掉；被擋下的每列只留名字、工具和位置，「為什麼被擋」在標題下寫一次，沒名字的（MCP）用檔名；「這次用了 N 次」改成「這個對話用了 N 次」
- 用別的帳號（例如 root）跑的 agent：標題列的 Kit 按鈕從「root 唯讀」改成「root · 這裡看不到」，彈出視窗第一句說「kit 照常能用」，看不到的是這個視窗（它用你的帳號跑），不是 agent 不能用
- 用 root 跑的 agent：那台有 root 每 10 分鐘寫的清單（/var/lib/kit-root-view/list.json）時，Kit 視窗列出它在用的規則、技能、MCP、外掛，只能看、沒有任何按鈕，按鈕旁寫「root · 只能看」；清單不在或超過 30 分鐘沒更新，照原本的字再加「清單沒有更新」
- Kit 視窗標題下面那行（機器・資料夾）拿掉，只留名字，讀取中看 ⟳ 在轉；用量視窗的那行多寫分頁名稱（例如「server · work / 1 · ~/app」）
## 1.10（2026-11-21）
- 「skill」「Skills」都改叫「技能」：倉庫的分頁、agent 標題列的 Kit 按鈕（規則 8 技能 8 MCP 1）、清單和說明都一樣；指令（kit add skill …）不變
- 「收來的」每一列和每一組不再掛藍底的「有新版」，改成淡色小字「新版」；標題那行只寫幾個有新版，幾小時前查的放在滑鼠停上去的提示，不會被切掉
- 送出、放行的訊息不重複「送出」、短句不加句號：「已放行，agentkit-library 已推上去」
## 1.9（2026-11-21）
- Kit 面板加上、拿掉、同步之後，已經開著的 agent 不用重開：同一台電腦、有讀到這個改動的 agent（整個帳號的改動：那個工具的每個 agent；加到資料夾的：在那個資料夾或底下的）會收到 `/reload-plugins`
  - Claude Code：plugin、MCP 重新載入；skill 它自己會看到，不送；規則（CLAUDE.md）要開新對話
  - omp：skill、plugin、MCP 重新載入；規則要開新對話
  - Codex：新的 skill 下一輪就看得到（試過 0.169），不送；plugin、MCP、規則要重開
- 它在等你、閒置或做完時馬上送；工作中或在等你回答就排隊（標題列寫「排隊重新載入」），停下來才送，一個 agent 只排一個，30 分鐘沒停就取消並通知
- 做完後訊息多一行，例如「t63、t96 已重新載入；t1p（Codex）要重開；t7z 要開新對話（規則）」
